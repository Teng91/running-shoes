# ADR-0014：可攜跑步前身 ID 與跨分頁刷新

- 狀態：Accepted
- 日期：2026-10-25
- 規格：[SPEC-034](../specs/034-portable-recovery-and-sync-refresh.md)

## Context

來源復原會取得新 PK，接收端單憑新 ID 無法辨識既有手動跑步。以內容猜測會合併使用者刻意新增的相同活動。浮點累積及跨分頁佇列消費也分別造成假更新與舊畫面。

## Decision

- archive v3 明確攜帶每筆跑步的同來源 aliases。舊 reader 拒絕未知版本；新版繼續讀取 v1/v2，指紋排除新增欄位。
- 同一來源鍵只能屬於一筆來源跑步；總量最多 50,000 且受 20 MiB 整體容量限制。匯出只取本人原生來源的存活對應，不攜帶其他來源或帳號的 mapping。
- 匯入以全部來源鍵查找本人對應，歧義安全拒絕，明確保留接收者刪除。寫入在原業務交易內保留全部別名。
- SQL 里程累積固定兩位；差異比較忽略既有尾差，不進行正式資料修整。
- controller 注入提交通知，bridge 用 BroadcastChannel 通知同帳號分頁重新讀取。手動及前景可獨立觸發；同時刷新合併，讀取中新增通知需 trailing read。通知不影響提交結果。

## Consequences

DB schema 6 不變，無需 migration。新 v3 檔案不能送入舊 App，需先更新接收端；不能移除別名繞過契約。已形成的重複紀錄不自行猜測或刪除。前端通知只提供讀取觸發，不承載憑證或業務寫入。
