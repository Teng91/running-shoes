# SPEC-146：執行環境升級到 Python 3.13

- 狀態：Implemented
- Owner：Running Shoes maintainers
- 關聯 issue／ADR：[SPEC-036](036-security-hardening-and-portable-locks.md)（跨平台鎖定檔）、[SPEC-134](134-account-keyed-settings-and-decoupling.md)（基底映像以 digest 固定）

## Problem

- 正式映像、CI 與 Ruff／mypy 都固定在 Python 3.11。3.11 只剩安全性修正，2027-10 結束支援；本機開發已經在 3.14 上執行，正式環境落後三個小版本。
- 版本寫在 Dockerfile、三個 workflow／composite action 的 `setup-python`、`pyproject.toml` 的 Ruff 與 mypy，以及 README 的鎖定檔編譯指令，沒有測試確認它們一致：只改其中一處，CI 測的版本就和上線的不同。

## Goals

- 正式映像改用以 digest 固定的 `python:3.13-slim`；CI 的每個 `setup-python`、Ruff `target-version`、mypy `python_version` 與 README 的 `uv pip compile --python-version` 都是 3.13。
- 鎖定檔以 3.13 重新編譯，套件版本與雜湊不變；每個鎖定套件在 Linux x86_64／aarch64 與 Windows 的 3.13 上都有可安裝的 wheel。
- 一個測試以 Dockerfile 的版本為準，確認上述設定一致。

## Non-goals

- 不直接升到 3.14：這次只換執行環境、不動套件版本；3.13 支援到 2029-10，3.14 另外評估。
- 不升級任何套件，也不為了新語法改寫既有程式；只修 Ruff 新目標檢查出的項目。
- 不改 schema、API、前端行為或 Fly 機器規格。

## Proposed design

- `Dockerfile`：`FROM python:3.13-slim@sha256:7249d558…`（3.13.18、Debian trixie 的多架構 index digest）；Dependabot 每月的 docker 更新照舊移動 digest。
- `.github/workflows/verify.yml`（`verify`、`diagnostics-roundtrip`）、`.github/workflows/offsite-backup.yml` 與 `.github/actions/browser-setup`：`python-version: "3.13"`。部署與回滾 job 不安裝 Python，不受影響。
- `pyproject.toml`：Ruff `target-version = "py313"`、mypy `python_version = "3.13"`。新目標只帶出兩個 UP043（`agent.run_agent_stream` 與 `services/reports.generate_report` 的 `Generator[X, None, None]` 改成 `Generator[X]`，3.13 的型別參數有預設值），只動型別註記；mypy 沒有新發現。
- 鎖定檔：照 README 以 `uv pip compile --universal --generate-hashes --python-version 3.13` 重新編譯。版本與雜湊不變，只少了 3.13 用不到的 `python_full_version >= '3.12'` 條件與幾行 via 註解；非 Windows 的 `uvloop` 與 Windows 的 `colorama` 條件保留。另以 `--python-platform x86_64-manylinux_2_28`／`aarch64-manylinux_2_28 --only-binary :all:` 解析確認 Linux 3.13 每個套件都有 wheel，並在 Windows 的 CPython 3.13 以 `--require-hashes` 安裝開發依賴、跑完 `verify`。
- `scripts/task.py` 的說明改為 3.13+；README 的技術選型、快速開始與部署圖寫 3.13。

## Security and data isolation

- 不改資料邊界、權限或 secret 處理；套件版本與雜湊不變，`pip-audit` 照常檢查。
- 3.13 的 `ssl.create_default_context()` 多了 `VERIFY_X509_STRICT` 與 `VERIFY_X509_PARTIAL_CHAIN`，SPEC-085 的 STARTTLS 會用更嚴格的憑證檢查；以 3.13 的預設 context 對 `smtp.gmail.com:587` 做 STARTTLS 已確認通過（TLS 1.3），上線後仍寄一次 email 驗證碼確認。

## Migration, rollout, and rollback

- Schema／資料 migration：無（schema 14 不變）；SQLite 資料庫檔與 v1–v6 帳號備份格式和 Python 版本無關。
- 上線與 smoke test：`verify.yml` 的部署前快照與 `release-check`；上線後寄一次 email 驗證碼確認 SMTP。
- 回滾方式與資料相容性：可直接回滾至 v5.4.0 image（Python 3.11）。schema 沒有變，部署後的 release-check 失敗時，[SPEC-144](144-ci-retry-diagnostics-and-rollback.md) 的 `rollback` job 會自動部署回上一版映像。volume 只放 SQLite 資料，`compileall` 產生的 bytecode 在映像內、跟著映像走，不需要清除。

## Acceptance criteria

- [x] AC-1：Given Dockerfile 的基底 `python:3.13-slim@sha256:…`，When 讀取 `.github` 下所有 workflow 與 composite action、`pyproject.toml` 與 README 的鎖定檔指令，Then 每個 `setup-python`、Ruff `target-version`、mypy `python_version` 與兩行 `uv pip compile --python-version` 都是 3.13，且 `verify` 的 Ruff 與 mypy 通過。
- [x] AC-2：Given 正式映像，When 檢查 Dockerfile，Then 基底是以 digest 固定的 `python:3.13-slim`，映像仍內含所有回滾腳本。
- [x] AC-3：Given 以 3.13 重新編譯的鎖定檔，When 檢查平台條件，Then 非 Windows 的 `uvloop` 與 Windows 的 `colorama` 條件仍在，兩份鎖定檔都能以 `--require-hashes` 安裝。
