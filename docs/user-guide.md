# Running Shoes 使用指南

## 平常怎麼用

1. 登入後，先在鞋款頁新增跑鞋。
2. 到跑步日誌選日期、公里數、鞋款，再按新增。連線時成功儲存的紀錄已在伺服器，不用另外按「立即同步」。
3. 用表單編輯鞋款、跑步、月跑量或目標後，按儲存才送出；在表格內直接編輯數字時，按 Enter 或離開欄位送出，Escape 取消。自動保留草稿不代表已儲存。
4. 需要處理離線紀錄、草稿、備份或誤刪時，開啟側欄的「資料與同步」。

## 「資料與同步」各區做什麼

| 功能 | 用途 | 是否改動伺服器資料 |
| --- | --- | --- |
| 本機待同步跑步／立即同步 | 將這台裝置離線新增的跑步送出 | 送出成功才新增跑步並更新統計 |
| 未完成的編輯草稿 | 找回尚未儲存的輸入，繼續編輯或捨棄 | 恢復草稿不會；仍需儲存 |
| 下載完整備份 JSON | 下載目前帳號在伺服器上的資料副本 | 不會 |
| 帳號資料匯入 | 預覽檔案，選擇只新增或新增並更新同來源資料 | 按「確認匯入」後才會 |
| 異動歷史與誤刪復原 | 查看異動及復原符合條件的刪除 | 按復原並成功後才會 |
| 清除此帳號的本機資料 | 清理此裝置中這個帳號的草稿、快取及待同步紀錄 | 不會刪除伺服器資料 |

### 立即同步：只送出本機待送的跑步

只有「新增跑步」支援離線送出；編輯、刪除及其他功能仍需連線。離線新增成功時，紀錄先保存在這個瀏覽器／裝置，尚未計入伺服器統計。

恢復網路並保持 App 開啟，或回到 App 前景時，系統會重試。也可以開啟「資料與同步」按「立即同步」。關閉 App 後不保證背景同步，所以離開前先確認沒有待同步紀錄。

- **目前沒有待同步的跑步紀錄**：沒有需要送出的資料，不用再按。它不會提交未儲存的表單，也不是從其他裝置重新下載所有資料的按鈕。
- **同步中／已同步幾筆**：等待完成，再查看剩餘筆數。
- **目前離線**：先連線，紀錄會繼續留在本機。
- **等待重試**：檢查連線與登入狀態；若其他分頁正在同步，稍候再試。
- **需要處理**：閱讀紀錄旁的原因。原鞋款已刪除時，明確選擇替代鞋款，再按「重新配對並重試」。配額或其他限制需先解決，不能只靠反覆按同步。
- **本機工作區尚未就緒／儲存不可用**：保留目前輸入，稍後重試或重新整理；確認瀏覽器允許網站儲存資料。無法保存本機資料時不要依賴離線新增。

「移除本機待送出紀錄」會丟棄這筆待送內容，不會撤銷伺服器已成功儲存的跑步。換裝置時看不到原裝置尚未同步的紀錄；請先在原裝置完成同步。

### 草稿：保留輸入，仍要儲存

新增跑步、月跑量及目標的輸入會自動帶回原表單；鞋款、跑步及月份的編輯草稿可在這裡按「繼續編輯」。確認內容後再儲存。「捨棄草稿」只刪除本機輸入，不會刪除已儲存的紀錄。

如果伺服器上的紀錄已被其他分頁／裝置修改，舊草稿儲存時可能顯示衝突；請以最新資料核對後再編輯。

### 下載目前帳號資料 JSON：雲端搬到本機版的第一步

JSON 是機器可讀的文字檔，供這個 App 合併還原使用，不需要自行修改。它包含鞋款、跑步日誌、月跑量、跑量目標、已儲存月報、Strava 匯入摘要及異動歷史。

它不包含密碼、登入憑證、本機草稿或尚未同步的跑步，也不是整個網站所有帳號的資料庫備份。檔案包含個人跑步資料，請保存在自己的安全位置。

備份步驟：

1. 先連線，在每個有離線紀錄的裝置完成同步。
2. 確認目前登入的是要備份的帳號。
3. 按「下載目前帳號資料 JSON」，將檔案保存到自己找得到的位置。下載中、完成或失敗會在按鈕下方顯示；檔案實際位置請查看瀏覽器下載項目。
4. 有重要新增資料後，重新下載一份；舊檔不會自動更新。

預設勾選「包含異動歷史」。如果提示歷史超過 50,000 筆，可自行取消勾選後再下載；檔名會標記 `_without_history`，畫面也會明示不含歷史，鞋款、跑步等資料仍保留。下載前會驗證格式及 20 MiB 容量，超限時不會產生無法匯入的檔案，也不會悄悄截斷資料。取消歷史後仍超限，需由管理員使用 README 的完整資料庫備份流程。

### 匯入到本機版：選擇只新增或更新先前匯入的資料

1. 如果要把雲端資料搬到本機，先開啟電腦上執行的本機版，再登入**本機版要接收資料的帳號**，開啟「資料與同步」。上方會顯示目前網站網址與帳號；匯入只寫入這個網站的此帳號。在雲端網站匯入就會寫到雲端，請先核對網址。
2. 在「選擇備份 JSON」選取這個 App 匯出的檔案，最多 20 MB。這裡不接受 Strava CSV，Strava 檔案請使用專用匯入功能。
3. 選擇「只新增，保留既有內容」或「新增並更新同來源資料（v2）」。閱讀預覽中的來源帳號、匯出時間、接收網站／帳號，以及新增、實際變更與內容相同的筆數。選檔／預覽還沒寫入資料，關閉視窗即可放棄。
4. 確定後按「確認匯入」。更新模式會再提醒哪些資料會覆寫。預覽有效 20 分鐘；期間帳號資料有變更，需按「重新預覽」。模式改變也必須重新預覽。

同帳號的多個預覽可以分別存在，晚到的舊請求不會撤銷新預覽。關閉視窗、換檔或換模式時會清理不再使用的預覽；清理遇到斷線，伺服器會在到期後回收。為限制暫存空間，每個帳號最多 8 份有效預覽、合計 64 MiB；遇到上限請關閉其他預覽或等待過期後重試。任一匯入真的改動資料後，其他舊預覽仍需重新產生。

如果顯示「匯入已完成，但畫面更新失敗」，按「重新載入資料」即可；這只重新讀取，不需要再次匯入。若提交本身連線中斷，保留原視窗並重試同一操作，以確認結果。

再次匯入相同內容不會增加未變更紀錄的版本或業務異動；原本編輯中的額外資料也不會僅因匯入而被判定為衝突。真正有變更時，版本檢查仍會保護較新的資料。

「只新增」保留既有內容，不更新已存在的鞋款、跑步、目標或月報，既有月份人工調整也保留。適合只補入缺少的資料。

「新增並更新」適合第二次下載雲端新版資料，再更新本機先前匯入的內容。它會按穩定來源身分更新鞋款及跑步，並更新檔案內同月份的人工調整、跑量目標及月報；跑步也用 Strava 活動身分去重。請先下載接收帳號原有資料的備份，因為這個模式可能覆寫本機修改。

例如雲端把鞋款暱稱改為「比賽鞋」、某筆跑步改成 8 km，再下載匯入本機：選「只新增」不會改既有紀錄；選「新增並更新」就會更新暱稱與該筆跑步，並重新計算里程。本機額外新增的跑步仍保留，所以本機總里程可能比來源檔案高。

兩種模式都不會刪除檔案未包含的本機資料，不是整個帳號的鏡像取代。不同來源但品牌、型號相同的鞋款，不會自動視為同一雙；不要把來自不同服務、未共享來源身分的資料視為同一筆。

目前 v2 備份依來源身分防止重建，也支援更新模式；舊 v1 只能選「只新增」，只保證完全相同檔案重複匯入不重建。已合併後又刪除的跑步，不會靠重複匯入撤銷後續刪除；更新模式會依檔案更新仍存在鞋款的刪除狀態。若要救回誤刪跑步，優先查看「異動歷史與誤刪復原」。匯入失敗不會只還原一半；超過帳號配額或備份限制時，先處理預覽／錯誤提示。

這項功能適合補入缺少的資料或搬移帳號資料；如果希望兩台裝置看到同一份最新資料，使用相同服務並登入同一帳號，完成同步後在另一裝置重新載入即可，不需要來回匯出匯入。

### 異動歷史與誤刪復原

這裡顯示目前帳號的已記錄異動。符合條件的刪除會提供「復原誤刪」，例如刪除跑步、鞋款或清除月份；復原仍會檢查目前資料、鞋款及配額，並重新計算里程。同一刪除只可復原一次。

它不是任意版本回溯工具；系統開始記錄前的異動不會補出歷史。從備份帶入的歷史只供查看，不能直接用來復原。

### 清除此帳號的本機資料：什麼時候用

適合在共用裝置使用完畢後，清理這個瀏覽器中目前帳號留下的內容。

- 會清除：這個帳號在此裝置的未完成草稿、最近資料快取，以及**尚未同步的跑步紀錄**。
- 不會刪除：伺服器已儲存資料、其他裝置資料、其他帳號的本機資料，或已下載的 JSON。
- 清除後，連線載入時可再取得伺服器資料；被清除的未同步紀錄及草稿則無法從伺服器找回。

操作前先確認待同步清單為空，並完成或捨棄需要的草稿。只下載 JSON 無法保住未同步紀錄或草稿。若只是資料顯示較舊，先重新整理，無需清除本機資料。

登出本身會保留本機資料，方便同帳號下次繼續；另一帳號無法顯示或同步它。清理完共用裝置後，再登出帳號。瀏覽器主動回收空間或手動清除網站資料也會移除本機內容，所以本機儲存不能取代完成同步與定期備份。
